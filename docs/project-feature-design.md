## 1. 定位（一句话）

**每个"项目"是一间独立的厨房**：项目自己的数据文件 + 自己的地图图层 + 自己的运行历史 + 自己的 Agent 记忆，
彼此互不干扰。切项目就是换一套上下文。

类比：
- **数据文件** = 原材料（面粉、菜）
- **工作区** = 一个料理台/储物柜
- **图层** = 端上桌的成品菜（地图上看到的那一层）
- **项目** = 一间独立的厨房

业界 GIS 工具常把"工作区"当作"一个项目"。区别在于：它们多以文件为锚，我们以**图层为锚、项目为壳**。

## 2. 每个项目包含什么

| 组成 | 内容 | 状态 |
|---|---|---|
| 项目信息 | 名称、描述、创建时间 | 新建 |
| 研究范围 | 边界图层（study_area），决定 Agent 分析范围 | 现有（单项目） |
| 数据文件 | 上传的 CSV/GeoJSON、OSM 下载物、execute_code 产物 | 部分现有（workspace/data、.workdir/） |
| 地图图层 | 该项目的图层面板 + 可见性 + 样式 + 分组 | 现有（需按项目隔离） |
| 运行历史 | 每次 Agent 对话的 RunArchive（追溯/工具调用/产物） | 现有（workspace/.workdir/runs/） |
| 项目记忆 | 项目范围、目标、偏好、已有图层、失败原因 | 待做（依赖 P6 记忆） |

## 3. 交互流程（目标形态）

1. 顶部栏**项目切换器**：显示当前项目名；下拉可新建 / 打开 / 删除项目
2. 新建项目 → 生成独立项目目录 + 空图层面板（研究范围待设）
3. 打开项目 → 加载该项目的图层、文件、历史；Agent 上下文随之切换
4. 删除项目 → 确认后移除该项目目录（含图层、文件、运行历史）

## 4. 与现有功能边界

- **本轮不改现有单项目行为**：当前演示仍是"默认项目"（研究范围 + 8 demo 图层）
- 项目隔离只在**多项目创建后**生效；单项目用户无感知
- 上传入口（POST /layers/upload）是项目功能的前置基础设施：上传的图层将来落在**当前项目**的数据空间
- 不做的：跨项目共享图层、跨项目合并、项目权限/协作

## 5. 实施建议（后续 sprint）

1. **时机**：在交互对齐 Sprint 2 之后（样式模型持久化、完整记忆落地后）
2. **存储**：workspace 切分为 `workspace/projects/<project_id>/`，每项目独立
   - `data/layers/` 图层文件
   - `.workdir/runs/` 运行历史
   - `memory.json` 项目记忆
3. **注册表**：`DATA_REGISTRY` 增加项目作用域访问器（当前为全局单例，需改造成可切换的上下文）
4. **前端**：TopBar 项目切换器 + 项目 CRUD；图层面板/成果栏随项目刷新
5. **演示口径不变**：确定性 GeoJSON、全部真计算

## 6. 项目面板设计（V1.1 补充确认）

> 借鉴典型 GIS 工作台左侧的资源树交互形态，**但内容换成我们的项目元素，不搬代码文件树**。

### 6.1 面板结构（去重版）

```
XX 街区现状研究                  ← 顶部：当前项目名 + 切换项目
├─ 📄 项目信息                    ← 名称/描述/创建时间
├─ 📦 数据文件                    ← 原料清单：上传/下载/生成的
│   ├─ 研究范围 · 已在地图上 ●
│   ├─ 学校设施 · 已在地图上 ●
│   ├─ 人口数据
│   └─ 公园绿地 · 已在地图上 ●
├─ 🗂️ 运行历史                    ← 每次 Agent 对话记录
└─ 🧠 项目记忆（后置，依赖 P6 记忆）← 项目在做什么、偏好
```

**已确认的两个决策：**
1. **不做"地图图层"分区**——图层管理已有左侧栏「数据」模块（LayerPanel），重复展示无意义。
2. **数据文件与图层用"绿点"联动**——数据文件带 `已在地图上 ●` 标记；双击该文件 → 跳转到「数据」模块定位对应图层。各管各的，不重叠。

### 6.2 数据文件行交互（借鉴 GIS 工具常见的右键菜单）

| 操作 | 说明 |
|---|---|
| 添加到地图 | 未上地图的 GIS 文件，一键发布为图层 |
| 预览 | 看数据长啥样（属性/几何预览） |
| 重命名 / 删除 | 管理项目文件 |
| 已在地图上 ● | 标记该文件对应图层已显示 |

### 6.3 与工具目录的关系

- 「文件与系统」分类（文件读写类工具全保留）是**项目功能的地基**：AI 读写项目文件靠它。
- 面板顶部"切换项目"＝切换整间厨房的上下文（数据文件/图层/历史/记忆）。

### 6.4 明确不做

- 不展示代码文件树（.py/.md/日志）——面向非开发用户。
- 不做跨项目共享图层 / 合并 / 权限 / 协作。
