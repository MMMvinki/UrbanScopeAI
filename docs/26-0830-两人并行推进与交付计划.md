# 26-0830 两人并行推进与交付计划

## 1. 文档目的

本计划供李工、缪工及双方使用的开发 Agent 共同阅读。

当前两人都是产品角色，具体代码工作可以交给各自的 Agent 完成。两人的重点不是按原来的三个业务 Part 平分，而是：

- 李工先独立推进“本地数据文件夹接入”，缪工同时继续基础能力工作；
- 缪工主导基础分析能力、统一结果和 Agent 主流程的打通；
- 李工后续重点定义组合分析、继续分析规则和产品验收，涉及 Agent 主流程的实现由缪工主导或审查；
- 两人最后通过一条共同案例验证数据、基础分析和组合分析能否真正接通。

## 2. 总体推进结构

```text
两条工作线同时推进
┌────────────────────────┬────────────────────────┐
│ 李工                    │ 缪工                    │
│ 本地数据文件夹接入       │ 基础能力和主流程         │
│ 组合问题与判断规则       │ 数据标准与基础指标       │
│ 继续分析的产品条件       │ Tool/Skill基础能力       │
│ 地图与结果验收           │ Agent执行与结果结构       │
└───────────┬────────────┴───────────┬────────────┘
            │                        │
            └──────────┬─────────────┘
                       ▼
阶段性汇合
真实数据接入基础分析，再接入组合诊断
                       ↓
共同跑通一条真实组合分析案例
```

其中：

- 工具（Tool）：执行一次明确、可验证的计算，例如等时圈、叠加、统计、核密度。
- 技能（Skill）：一套可复用的专业分析方法；可以指导 Agent 组合多个工具，也可以封装一个确定性分析脚本。
- 智能体（Agent）：理解用户问题，选择工具和技能，并根据结果决定下一步。
- 按需启用：系统先知道数据在哪里，真正需要分析时才读取，不在启动时把全部数据载入内存。

## 3. 第一阶段：李工先完成本地数据文件夹接入

### 3.1 当前问题

当前页面主要采用单文件上传，操作繁琐，大型 POI、人口、客流和 Shapefile 数据不适合逐个上传或全部转成 GeoJSON 后加载。

### 3.2 总体目标

```text
用户配置或链接一个本地数据文件夹
        ↓
系统只读扫描文件夹
        ↓
形成可查看的数据目录
        ↓
显示文件、格式、大小、字段、坐标和可用状态
        ↓
根据数据状态决定：直接启用、仅供查询或暂不可用
```

当前项目还没有“外部数据目录”这一层，只有“已经加载的地图图层”。因此本功能必须区分：

- 数据目录：记录文件夹中发现了哪些数据；
- 地图图层：已经被选择、加载，可以显示和参与分析的数据。

扫描成功不等于可以直接加载，更不等于已经可以被 Agent 分析。

### 3.3 分三步实施

#### 3.3.1 第一步：只读发现

- 在本地部署环境中配置允许访问的数据根目录；
- 扫描文件夹并形成数据目录；
- 展示文件格式、大小、字段、坐标、几何类型和状态；
- 保存项目与数据源的关联，重启后可以恢复；
- 本步骤不要求把数据注册为地图图层。

#### 3.3.2 第二步：小数据启用

- 只对规模安全、格式和坐标明确的数据开放“启用”；
- 优先支持小型 GeoJSON、WGS84 Shapefile 和坐标明确的小型 CSV；
- 启用后才进入当前地图图层和分析工具体系；
- 数据规模、坐标或编码不明确时不得强行启用。

#### 3.3.3 第三步：大型数据查询

- 大型 POI、人口和客流数据不应全部转成 GeoJSON；
- 应支持按字段、空间范围或统计任务读取；
- 地图只加载必要的局部结果或聚合结果；
- 该步骤可以与缪工后续基础分析能力共同设计，不要求文件夹接入 Agent 第一轮全部完成。

### 3.4 必须遵守的边界

1. 不修改、删除或移动任何原始数据。
2. 不把整个文件夹复制到项目工作区。
3. 不在扫描时把所有数据加载到地图或内存。
4. 对大型 CSV 只读取表头和少量样本，不全量转 GeoJSON。
5. 能识别常见的 CSV、XLSX、GeoJSON、Shapefile、ZIP Shapefile 和 GeoPackage。
6. Shapefile 的 `.shp/.dbf/.shx/.prj` 应视为同一个数据集。
7. 第一版仅面向本地部署；允许访问的数据根目录由本机配置，项目只保存数据源别名和相对路径，不把个人电脑绝对路径写死并提交到 Git。
8. 记录数据来源、格式、文件大小、主要字段、坐标信息和当前可用状态。
9. 对暂时无法直接使用的数据明确显示原因，不伪装成可用。
10. 保留未来接入 GDB 和大型数据按范围查询的扩展位置，但第一阶段不强求全部完成。

### 3.5 数据状态

页面至少区分以下状态：

```text
已发现：系统知道文件存在，但还没有完成全部检查
可直接启用：规模、格式、字段和坐标满足当前加载能力
仅可查询：数据较大，不适合完整加载，只能按范围或任务读取
暂不可用：格式、坐标、字段或依赖条件不满足，并显示原因
```

### 3.6 优先验证的数据

- 地铁出入口；
- 商业 POI；
- 昼间和夜间活力数据。

### 3.7 第一步“只读发现”完成标准

1. 用户能够在数据页面看到“链接本地数据目录”入口。
2. 系统能够扫描指定的乐活大道数据目录。
3. 页面能够列出至少地铁、商业 POI、昼夜活力三类数据。
4. 能查看每个数据的基础信息和可用状态。
5. 大型数据不会因扫描而被全部读入内存或发送到浏览器。
6. 关闭并重启项目后，已链接的数据源配置仍能恢复。
7. 原始数据内容和修改时间不发生变化。

### 3.8 第二步“小数据启用”完成标准

1. 能选择至少一个安全规模、坐标明确的数据启用为项目图层。
2. 启用前显示数据规模、坐标和可能的质量警告。
3. 启用后能够在地图显示，并能被现有 `list_datasets` 等分析工具发现。
4. 大型数据保持“仅可查询”，不会调用现有全量 GeoJSON 转换路径。

## 4. 第二阶段：缪工主导基础能力和主流程

缪工负责让系统具备稳定、可重复使用的分析底座。

主要包括：

1. 统一数据字段、坐标、空间范围和分析单元。
2. 打通基础统计、密度、核密度、覆盖、叠加、等时圈等工具。
3. 修正缺少真实数据时仍返回演示数值的问题。
4. 统一每一步分析结果必须返回的指标、图层、数据来源、参数和警告。
5. 建立基础 Skill，例如人口活力、商业结构、轨道可达性和公共服务可达性。
6. 让 Agent 能够稳定选择工具和技能，并保存真实执行过程。
7. 对缺数据、坐标不明、计算失败等情况明确停止或提示。
8. 为后续组合分析提供标准化的基础结果。
9. 增加分析层级、步骤依赖、结构化发现、继续分析建议和停止原因。
10. 为 Agent 设置最大分析深度、最大工具调用数、时间限制和“无新发现即停止”等边界。
11. 区分普通半径覆盖与真实路网等时圈，不允许用圆形缓冲冒充步行等时圈。

组合分析正式接入前，缪工需要先交付统一结果格式。至少能够表达：

```text
指标名称和值
空间范围或空间单元
结果图层
原始数据来源
计算方法与参数
分类或判断规则
质量警告
结构化发现
推荐继续分析的问题
停止原因
```

缪工交付给组合分析使用的基础结果至少包括：

```text
空间单元编号
居住人口
就业人口
昼间活力
夜间活力
商业数量
商业密度
商业混合度
轨道可达性
公园可达性
公共服务可达性
结果图层
数据来源
计算参数
质量警告
```

## 5. 第二阶段：李工重点推进组合分析与产品验收

李工后续重点不是重复开发基础统计，而是回答：

> 多种基础结果放到一起以后，能够发现什么问题；发现问题后，系统应该继续检查什么。

李工负责产品规则、展示结果和验收标准；涉及 Agent 主循环、统一结果模型和公共 Tool/Skill 的代码实现，由缪工主导或合并前审查。

### 5.1 优先组合分析

#### 轨道可达性 × 商业供给

- 高轨道可达—低商业供给；
- 低轨道可达—高商业集聚；
- 高轨道可达—高商业集聚；
- 低轨道可达—低商业供给。

#### 公园可达性 × 人群活力

- 高可达—低活力；
- 低可达—高活力；
- 高可达—高活力；
- 低可达—低活力。

公园可达性应从公园出入口计算，不能默认使用公园中心点。

#### 商业供给 × 昼夜活力

- 昼间高活力—低商业供给；
- 夜间高活力—低商业供给；
- 低活力—高商业供给；
- 高活力—高商业供给；
- 日间高、夜间低的商务潮汐区；
- 夜间高、日间低的生活消费区。

### 5.2 李工需要定义的产品内容

1. 哪两个或多个指标参与比较。
2. “高”和“低”按什么规则判断。
3. 每一种组合类型代表什么业务含义。
4. 地图上应生成什么分类图层。
5. 结果卡需要显示哪些数字。
6. 哪些发现应该触发继续分析。
7. 数据不足时系统应该怎样提示。
8. 什么情况下分析应当停止。
9. 每条结论需要引用哪些数据和图层作为证据。

### 5.3 分析层级

```text
第0层：数据准备
找到数据、检查字段和坐标、按需启用
        ↓
第1层：基础描述
有什么、多少、占比是多少
        ↓
第2层：空间分析
在哪里集中、哪里不足、是否可达
        ↓
第3层：组合诊断
人口、活力、商业、交通是否错位
        ↓
第4层：继续分析与行动解释
为什么出现、还要检查什么、可以怎样改善
```

李工主要关注第3层和第4层的产品定义及验收，但需要使用缪工提供的第1层、第2层基础结果。

上述层级不是每个问题都必须从第0层按顺序执行到第4层。Agent 可以从用户问题对应的层级开始，但必须先检查依赖的基础数据和指标；只有发现值得继续、数据满足且执行预算允许时，才进入下一层。

## 6. 程序处理结构

```text
用户问题
        ↓
智能体（Agent）：理解问题、检查数据、生成计划
        ↓
选择执行方式
├── 读取技能（Skill）的方法，再组合一个或多个工具
└── 直接调用工具（Tool）
        ↓
工具读取已启用数据并执行真实计算
        ↓
标准分析结果返回 Agent
        ↓
Agent检查结构化发现
├── 值得继续且预算允许：追加下一步
└── 不需继续或条件不足：形成结论并说明停止原因
        ↓
地图图层、指标、结构化发现和报告
```

“结构化发现”指一条包含空间范围、指标值、判断规则、证据和后续建议的正式分析结果，而不是一段无法验证的自由文字。

## 7. 第三阶段：共同验收主线

共同验收案例不是限制工作范围，而是用于验证双方成果能否接通。

开始本案例前必须满足：

1. 已验证地铁入口、商业 POI 和昼夜活力数据的坐标和关键字段。
2. 已明确共同空间分析单元以及“高/低”的判断规则。
3. 已配置并实测 Mapbox 等时圈服务，或者已有真实本地路网可达性能力。
4. 不允许用普通圆形缓冲代替真实步行等时圈而不作说明。
5. 已关闭空间叠加、密度、覆盖和供需工具的演示数值成功回退。
6. 基础结果能够携带数据来源、参数、质量警告和真实结果图层。

```text
链接乐活大道数据目录
        ↓
启用地铁入口、商业 POI、昼夜活力数据
        ↓
完成商业数量、密度和混合度
        ↓
完成轨道5/10/15分钟可达性
        ↓
识别高轨道可达—低商业供给区域
        ↓
Agent继续检查昼间和夜间活力
        ↓
判断为潜在商业缺口或当前需求不足
        ↓
输出地图、指标、证据、解释和后续建议
```

共同验收时必须确认：

- 使用真实原始数据；
- 没有使用演示数值补缺；
- 每个数字能够追溯到数据和参数；
- 地图存在对应结果图层；
- 组合分类规则明确；
- Agent继续分析有明确原因；
- 达到停止条件后能够正常结束。

## 9. 当前代码能力与边界

本节用于提醒双方 Agent 区分“当前已经具备的能力”和“本计划希望实现的能力”。

### 9.1 当前已经具备

- Planner 生成计划，Executor 连续调用多个工具；
- 工具调用结果会返回 Agent，模型可以据此继续选择工具；
- Tool Registry 提供统一工具参数定义；
- 工作流型和脚本型两类 Skill；
- 单文件上传、小型 GeoJSON 图层注册、项目图层持久化；
- Buffer、核密度、空间裁剪、Mapbox 等时圈等部分真实 GIS 能力；
- SSE 实时执行事件、运行记录、用户取消。

### 9.2 当前尚未具备

- 外部文件夹数据目录；
- “已发现数据”和“已加载图层”的正式区分；
- 大型 CSV/POI 按范围和字段查询；
- 原始数据与派生数据的血缘字段；
- 第0—4层的正式分析状态；
- 步骤依赖、计划修订、最大深度和明确停止原因；
- 统一的指标、质量警告、结构化发现和后续建议模型；
- 商业混合度、昼夜活力、通用四象限耦合等领域工具；
- 公园真实出入口数据的确认和接入。

### 9.3 当前必须先处理的风险

- 部分分析工具在真实计算失败时仍返回成功的演示数值；
- CSV 坐标列识别不等于完成 GCJ-02、BD-09、WGS84 转换；
- 普通点密度、供需和覆盖工具不能直接满足本计划中的组合分析口径；
- 当前 Mapbox 等时圈需要外部 Token；
- 当前仓库内平台图层和演示图层清单为空，乐活大道数据也尚未被运行时代码引用；
- 前端计划步骤状态是按顺序模拟推进，不能作为真实步骤对应关系。

### 9.4 数据目录向基础分析的交接信息

文件夹接入完成后，至少应向后续分析提供：

```text
稳定的数据集编号
数据源别名与相对路径
数据格式和大小
字段信息
坐标信息及可信状态
时间范围
当前状态：已发现/可直接启用/仅可查询/暂不可用
启用后的图层编号（如有）
质量警告
原始数据标识
```
