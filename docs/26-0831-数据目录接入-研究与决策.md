# 26-0831 数据目录接入 · 研究与决策

> 记录本功能（文件接入/管理）三阶段的**关键决策与原因**，供后续决策参考。要点：① FileGDB SDK/ArcPy 为何不引入；② 大型数据「预览」的真实定位；③ 下载目录与链接目录的关系；④ 栅格/CAD 的取舍。

## 一、File GDB 读取：为什么用 OpenFileGDB，不引入 FileGDB SDK / ArcPy

**结论**：用项目已有的 fiona 自带的 **OpenFileGDB** 驱动（GDAL 内置）读 gdb，零新依赖、开源、够用。

三个候选对比：

| 方案 | 性质 | 具体原因（为什么不选/为什么选） |
|---|---|---|
| **FileGDB API SDK**（Esri 官方） | 闭源 C++ 二进制库 | ① 免费下载但**闭源**，只给编译好的 .dll/.so；② **许可证限制**：不能重新分发、不能打包进第三方产品、限 Esri 生态内使用；③ 只有 C++ API，Python 需第三方绑定（pyfilegdb，第三方维护、多年不更新、Windows 编译困难）；④ 本项目是 Python/FastAPI 后端，引入 C++ 二进制库意味着每台部署机要装对应平台的 .dll，打包/迁移成本高；⑤ 它本身也只读，要写 gdb 还需额外授权。 |
| **ArcPy** | ArcGIS 授权环境 | ① 需安装 **ArcGIS Pro/ArcMap**（付费，每席位数千美元/年）；② ArcPy 只能跑在 ArcGIS 自带的 Python 环境里，**无法独立部署**、无法集成进 FastAPI 后端；③ 对一个开源/轻量部署的平台是巨大负担。 |
| **OpenFileGDB**（采用） | GDAL 开源驱动 | ① 开源、免费、随 GDAL 打包；② fiona 直接支持，`listlayers` 列图层、`open(gdb, layer=…)` 读 schema/要素数/CRS，**零新增依赖**；③ 只读——但平台本就只读原始数据、不写 gdb，够用。 |

**实测**：`乐活大道数据库.gdb`（260MB）展开出 55 个内部图层，可读 schema/要素数/CRS，小图层完整启用、大图层抽稀预览。局限是只读 + 对损坏的 gdb 可能读不全，但不影响当前数据。

## 二、大型数据「预览」的真实定位（重要澄清）

**不是「载入文件夹时就预览」，而是「用户明确选择某数据、确认要进平台」时才做。**

两个动作严格区分：

| 动作 | 触发时机 | 读多少 |
|---|---|---|
| **扫描**（链接文件夹） | 链接/重扫目录时 | **只读表头 + 元数据**（前 8KB、字段、坐标列、要素数），**绝不读数据行、绝不转 GeoJSON** |
| **预览启用** | 用户点某个大型数据的「预览启用」按钮 | 才流式**抽稀到 5 万要素**，不全量加载 |

所以「扫描 299MB POI」这一动作本身是零预览的——它只识别「这是 94 万点、有 lon/lat、太大不能完整启用」，标「仅可查询」。只有用户真的点「预览启用」时，才触发抽稀（实测 4.8s）。大型数据的**完整使用**（按范围/字段查询）留给后续第三步，与缪工的基础分析共同设计。

## 三、下载目录与链接目录的关系（第三阶段决策）

**结论：下载目录 = 一个特殊的「链接目录」，二者共用同一套扫描/管理机制，不另起炉灶。**

同事的痛点：从网上下高德/OSM/百度慧眼数据，文件大、散乱、难管理。

决策：
- 引入「**下载目录**」配置：用户设置一个本地文件夹作为联网取数（OSM/高德/datasource）的默认落盘位置。
- 该目录**自动加入白名单 + 自动链接为数据源**（别名「下载数据」），与「链接本地数据目录」完全同一套扫描/启用/目录树展示。
- 下载落盘后**自动重扫**该数据源，新下载的数据即时出现在左侧「本地数据目录」面板。
- 三处下载（datasource/OSM/amap）共用 `data_download.resolve_download_output` 落盘决策，避免重复逻辑。

**为什么不做成独立两套**：下载数据和本地原始数据本质都是「本地文件夹里的 GIS 数据」，用同一套「发现 → 查看 → 启用」能力覆盖，交互统一、代码不重复。上传文件/链接目录/下载目录三者在左侧数据面板汇合，都落到同一套数据目录树里。

**已知限制**：下载目录的数据靠「链接目录 + 启用」使用（`enable_dataset` 直接读文件）；Agent 的 `register_layer` 工具仍限定 workspace 内，暂不能直接注册下载目录里的文件——后续若要让 Agent 直接注册下载目录数据，再放宽该边界。

## 四、栅格 / CAD / 地图包：暂缓，取舍如下

| 格式 | 为什么不支持 | 替代路径 |
|---|---|---|
| 栅格 .tif（291MB 底图） | 需切 Web Mercator 瓦片金字塔（gdal2tiles）+ 前端 raster 图层渲染，一次性离线成本高；底图是参考底图非计算层 | 第三步「重图层按需加载」时一起做 |
| CAD .dwg | 需 ODA Teigha 或 GDAL DWG 驱动（额外编译），或转换工具 | 用 ArcGIS/QGIS 导出为 Shapefile 后接入 |
| .mpk / .lyrx / .aprx / .mxd | Esri 专有工程/打包格式，需 ArcPy 授权 | 属人工出图工程，不进平台计算 |

这些按数据体系分类说明属「人工分析后期数据/工程」，只作对照参考。

## 五、一句话总结

乐活大道全部计算输入数据（CSV/Shapefile/GeoJSON/GPKG/File GDB 及内部图层）已可识别、查看、启用；大型矢量数据抽稀预览、后续按范围查询；下载数据统一落到下载目录并被同一套目录树管理；栅格/CAD/地图包走「导出标准格式」替代路径。
