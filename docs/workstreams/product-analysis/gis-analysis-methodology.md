# UrbanScopeAI GIS 分析方法论（后续 GIS 分析 agent / Skill 必读）

> 本文档为平台「栅格网格类产品 / 密度面 / 可达性」产出时**必须遵守**的通用方法与口径纪律。
> 面向读者：后续任何新建或修改 GIS 分析 Skill、给数值面设置分档色、产出密度图层、写等时圈
> 统计口径的开发 Agent。真计算原则、坐标系、数据来源红线以仓库《26-0831-组合分析规格与验收设计.md》
> 与项目硬规则为准；本文只写「方法怎么选、为什么、口径怎么说才不误导」。
> 更新日志：2026-09-03 初稿（D0）。

## 0. 一句话总纲

**地图上能展示的量有三种来源：真实点/线/面要素、把点聚合成的分析网格（栅格产品）、以及算法算出的连续面（等时圈/覆盖带/密度面）。给「算出来的面」设色、分区、取名、配口径说明时，最容易犯的错是把它们当成「真实测量」、把分级阈值当成「客观事实」、把几何近似当成「可达」。本文把这些错列出来并给出替代做法。**

---

## 1. 术语：网格 / 栅格 / 面 / raster（瓦片）不要混称

| 词 | 含义 | 平台表达 |
|---|---|---|
| **分析网格 / 网格（grid）** | 把研究区切成规则格网（100m / 500m），把点/值聚合进格心或格内计数的产品 | 中文 UI 一律叫「栅格/网格」；图层语义 `kind='grid'` |
| **栅格（raster，瓦片）** | 真正按瓦片金字塔渲染的位图图层（平台底图/影像），几何上不是 Feature | 只 `kind='raster'` 走瓦片；前端不拉 GeoJSON |
| **面（polygon）** | 真实的多边形要素：研究区边界、等时圈、缓冲区、网格的几何外壳都可画成 polygon | 真 polygon（等时圈/缓冲区）UI 叫「面」 |
| **连续面/密度面（kernel density surface）** | 由核密度/平滑把稀疏点摊成连续数值场再抽样到网格的产品 | 属网格产品的进阶，仍叫「栅格/网格」，口径必须注明「密度估计」 |

规则：
- 网格产品不要叫「面」——它是聚合结果不是真实地块；
- 只有「真 polygon 要素」（边界、等时圈带、几何缓冲）才在 UI 语义上叫「面」；
- 一个图层是「网格产品」还是「真 polygon」，看它在**数据里是什么几何 + 是什么来源**（聚合 vs 真实），
  不是看渲染出来像不像。判据写进图层元数据（`kind`），前端按元数据显示标签，不靠猜。

## 2. 数值分级（choropleth 分档）方法怎么选

分档方法（quantile / natural-breaks(Jenks) / geometric-interval / equal-interval / stddev）把一段连续值切成几档再设色。
**没有「客观上正确」的分法**，每种都在「类间差异是否被尊重」与「各档数量是否均衡、图是否可读」之间取舍：

| 方法 | 原理 | 适合 | 坑 |
|---|---|---|---|
| **Quantile 分位数** | 每档要素数相等（5 档=每档 20%） | 密度网格等「要看出高/低区位排序」的产品；平台密度网格默认用它 | 会把几乎相等的值拆到两档（放大微小差异）；也会把差异很大的值并进同档（藏住真实断点）|
| **Natural Breaks (Jenks)** | 类内方差最小、类间最大，找自然断点 | 分布有天然簇（如商业密度多极集聚）时 | 断点数值不整、不可解释；遇伪簇会误导；O(k·n²) 需采样 |
| **Geometric Interval** | 档宽按等比级数增长（近似 log 尺度） | 强右偏/长尾/大量 0 与重复值的数据（如人口/设施计数） | 低档太宽高档太细，读者难解释 |
| **Equal Interval** | 全幅等距切 | 量纲读者熟悉的、呈钟形分布的量 | 偏态数据下绝大多数要素挤进最低/高一档 |
| **Standard Deviation** | 均值 ± σ 对称切 | 近似正态、想表达「偏离均值」的量 | 偏态下无效 |

平台默认与建议：
1. **密度/活力等网格产品默认 Quantile（5–7 档）**——它保证每档有可比数量的格，视觉上不会有「一大片同色 + 一两格跳色」的压迫；
   数据呈明显多簇时换 **Jenks**（人口、商业密度这类天然分簇的量尤其合适）。
2. **展示口径与统计口径解耦**：分档只为「看图」，档边界不是统计事实；页面/图例要能显示真实的密度阈值数字，而不是只给「高/中/低」。
3. 需要**跨区域/跨时间可比**的正式图，分档断点必须固定（manual/equal），不能每张图各算一次 quantile/jenks——
   数据驱动的分档会随范围变化而漂移，两图直接比会误读（来源：ESRI 分类方法文档，见 §6 引用 1）。
4. 档内断点由引擎统一算（`layer_style.compute_breaks`），采样只影响显示不改变统计；唯一值不足 k 档时退回真实唯一值边界，不伪造断点。

## 3. 稀疏点密度平滑（KDE / 焦窗均值）与「无设施」档

把稀疏设施点（如某一功能组的 POI 只有几十几百个）直接放进 100m 格计数，会得到大量 0 和零星 1~2 的
「胡椒粉图」，读不出空间结构。改进是**平滑**：核密度估计（KDE）或焦窗均值。做平滑必须同时处理三件事：

1. **带宽（bandwidth / search radius）怎么定**：
   - ArcGIS/多数工具默认带宽按 **Silverman 规则**（带宽与样本量 n 与标准差有关，n 越小带宽越大）取（§6 引用 2）；
   - **平台不用 150m 封顶的过窄核**——设施稀疏时 150m 几乎退化成逐格计数；
   - 实用做法：以「你希望 500m / 800m 这种『邻里尺度』上看到的集聚」为目标，固定带宽（如 300–800m，按数据点疏密自述），
     或按各功能组点集的 Silverman 规则算一个再人工取整；**带宽值必须写进口径与 SKILL.md**。
2. **边缘效应（edge effect）**：研究区边界外的点对区内靠近边界的格有贡献。研究区内的点在边界附近密度被低估。
   处理：做平滑时把范围外扩一个带宽内的点一起算，再裁剪回研究区；文档注明「边缘 1 个带宽内的密度受边界截断影响」。
3. **保留「无设施」档，不要伪 0 连续面**：
   - KDE 输出在每个格都有个密度小数值——**这不是「这里有一定设施」，而是「附近没有设施」**；
   - 产品表达上必须留一个「无设施 / 低于可检出门槛」的低档（近底浅色），不能把整片无点区渲染成「均匀低密度」的
     连续面，让读者以为全区都有设施只是多少不同；
   - 口径句写成「设施密度估计（核带宽 X m，含边缘截断说明），无设施区域单独标注，非逐格设施计数」。

## 4. 等时圈 / 可达性口径：累计机会法与阈值任意性

平台的等时圈只允许来自**真实路网步行**服务输出（Mapbox Isochrone walking 5/10/15 等），
500m 直线圆、曼哈顿/欧氏近似、手绘一律不是可达（红线见 72A §4.3/4.4 与《26-0831》）。

可达统计的常见口径与它们的「话术陷阱」：

- **累计机会（cumulative opportunities）**：从中心出发 X 分钟内能到的设施/商业点数。5 ⊆ 10 ⊆ 15 天然累计，
  每点只被并集几何计一次（跨中心用空间并集去重）。这是目前唯一用「个数」表达可达的诚实口径。
- **覆盖率（% 面积 / % 点）**：分母必须写清：研究区总面积？区内设施总数？「≤15 分钟覆盖到 X km² = 全区的 Y%」；
  不许只留一个孤零零的百分比让人猜分母。
- **阈值任意性（threshold arbitrariness）**：为什么是 5/10/15 分钟？因为它们只是约定俗成的演示档位，不是客观事实。
  因此：
  1. 分钟档必须与图层上的带一一对应、标注「真实路网步行 · N 分钟」；
  2. 统计给「每档面积/点数的单调递增」，不许只挑一档当「覆盖率」；
  3. 结论说「可达」必须限定「在这个分钟档与真实路网条件下」，说「难达」必须给难达区几何与面积，
     不能只说百分比。

守恒自检：**≤5 带 + (5,10] + (10,15] + 难达区 = 研究区总面积**。跑任何可达统计都把这条当断言写进测试。

## 5. 点符号 / 密度随范围与缩放自适应的原则

固定大点（radius=固定 5px）在几十万点全图缩放下必然互相堆叠、盖死地图。原则：

1. **点尺寸随视图缩放自适应**：deck 用 `radiusMinPixels / radiusMaxPixels` 做像素下限/上限，
   让点在放大的地图上有稳定可读大小、缩小到全图时不至于互相叠成一片。
2. **密度大时用显示抽稀，统计永远用全量**：数万到几十万点全图显示时，按类别抽稀或降不透明度——只改画面，
   要素计数/统计仍用全量 `feature_count` 与全量空间计算，抽样数绝不冒充总量（平台铁律）。
   放大到相应尺度逐点显现。
3. **点永远在面上层**，实色 + 白描边或细描边；栅格主图半透明，别把点盖没。
4. 图上/图例上点的大小或密度表达要与右侧指标卡同源（同一份 stats），点击图例或柱可过滤对应类别格/点。

## 6. 可修改面元问题（MAUP）提醒

任何「网格大小 / 边界怎么切」都会改变结论，这叫**可修改面元问题（Modifiable Areal Unit Problem, MAUP）**：

- **尺度效应**：500m 格与 100m 格会给出不同的集聚形态与数量。网格大小是**分析选择**，不是数据固有属性——
  选完必须写进图层名（`_100m` / `_500m`）与口径，换网格大小必须重算并说明数字会变。
- **分区效应**：同一批点换一种格网起止对齐，落在哪些格的计数就变。格网起点/分辨率固定到版本里（`GRID_VERSION`）。
- 由网格算出的「高/低供给」「高/低活力」是**相对该网格与阈值**的判断，不是地块本身的属性；边界句要带「该口径下 / 候选」。
- 阈值若用中位数，那就是「当前范围内相对多/少」，天然是相对口径，不许写成绝对结论。

**工程提醒**：改了 CELL_SIZE / GRID_VERSION 而数字变多/变少不是 bug——重算前把旧版本结果保留对比，
在交付说明里写「新口径重算，数字与旧版不可横比」。

## 7. 数据与红线提醒（每条都对应既有平台铁律）

1. 数字只来自真实原始数据文件；旧 PPT、派生汇总表、硬编码的验收值只作表达参考，不输入计算。
2. 统计一律全量；抽样只影响显示。
3. 可达性只允许真实路网 walking 等时圈；`coverage.stable_rate` 演示兜底、500m 直线圆冒充分钟可达、
   任何 `nan`/出口编号冒充站名一律禁止；失败诚实停止并写明原因。
4. `MAPBOX_TOKEN` 绝不进日志/输出/入库；只在进程 env 或 `.env` 读取。
5. 网格/栅格中文名用「栅格/网格」；出入口聚簇只称「出入口簇/代表出入口」，无权威站名关系前不称地铁站。
