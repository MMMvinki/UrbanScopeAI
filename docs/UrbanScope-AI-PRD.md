**文档信息**

### 1. 需求背景

UrbanScope AI 是面向城市规划前期现状分析的 AI 空间分析工作台。产品不定位为城市体检平台，也不定位为通用 GIS 软件，而是帮助规划师把自然语言提出的规划问题，转化为可执行、可追溯、可验证的空间数据分析流程和成果。

城市体检是 MVP 阶段的首个 Planning Skill，用于验证 Agent 能否完成“数据检查 -> 计划生成 -> 工具调用 -> 地图结果 -> 成果解释 -> 继续追问”的闭环。产品后续可拓展到公共服务设施评估、15 分钟生活圈、产业交通可达性、职住平衡、TOD、慢行友好度等现状分析专题。

**目标用户现状**

城市规划师在项目前期研究阶段经常需要处理人口、产业、公共服务设施、交通、用地、街区边界等空间数据。他们熟悉规划问题和业务判断，但大量时间消耗在找数据、清洗字段、坐标转换、裁剪范围、叠加分析、统计指标、制图和整理结论上。

**核心痛点**

规划师知道想研究什么问题，但每次都要手动组织数据和 GIS 操作；固定一键分析又无法覆盖真实项目中的数据缺失、字段不统一、临时追问和跨专题分析。

| 问题点 | 问题描述 | 当前影响 |
|---|---|---|
| 数据不确定 | 图层来源、字段含义、坐标系、数据质量不统一 | 分析前需要大量人工检查和整理 |
| 流程重复 | 覆盖率、叠加、距离、统计等操作反复出现 | 消耗规划师时间，难以沉淀方法 |
| 固定流程不够灵活 | 城市体检等场景有 workflow，但真实研究经常有追问 | 一键分析难以处理开放问题 |
| AI 结果不可信 | 如果 AI 只输出文字，无法验证依据 | 难以用于专业规划成果 |

### 2. 需求目标

**业务目标**

- 在比赛 Demo 中证明：Agent 能围绕规划现状分析问题，自动检查数据、生成计划、调用 GIS/统计工具并输出可追溯成果。
- 用“街区城市体检”作为首个 Planning Skill，同时通过 Open Analysis 展示通用数据处理和空间分析能力。
- 建立可扩展的 Agent 架构：Planner、Executor、Memory、Tool Registry、Data Readiness Check。

**成功标准**

| 指标 | 当前状态 | 目标状态 |
|---|---|---|
| 完整 Demo 闭环 | 无 | 用户一句话触发分析，系统输出 Plan、Trace、地图图层、右侧成果栏 |
| 数据就绪性检查 | 无 | 分析前能判断缺少哪些图层/字段，并询问上传、启用平台数据、替代或跳过 |
| 空间分析可信度 | 无 | 每个结论能关联到数据、Tool Trace、图层和结构化结果 |
| 通用分析能力展示 | 不明确 | 支持至少 2 个 Open Analysis 演示问题，不写死成按钮 |

### 3. 需求范围

**包含**

- Web App 工作台，采用左侧窄导航 + 左侧功能面板/Agent 对话 + 中央地图 + 右侧成果栏。
- Agent 对话式规划分析，支持用户右侧气泡、Agent 左侧气泡、流式输出、可折叠 Plan/Trace/数据检查。
- 数据图层管理，支持平台数据、用户上传数据、分析生成图层统一管理。
- 分析入口，作为 Planning Skills 和常用空间分析模板的启动器。
- 街区城市体检父 Skill 与 4 个 Indicator Skills 的 MVP 分层实现。
- Open Analysis 模式，支持基于现有数据和 Tools 的自由追问。
- Planner + Executor + Memory + Tool Registry 架构。
- MapLibre/deck.gl 地图工作区和右侧成果栏。
- 参考 Verdana Health Design System 的视觉风格。

**不包含**

- Agent Cards。
- 底部图层/Widgets 面板。
- 完整报告系统。
- 团队协作、权限体系、审批、版本管理。
- 完整数据市场、Skill Marketplace。
- 完整自动联网数据采集。
- 完整替代 ArcGIS/QGIS 的通用 GIS 软件能力。

## 二、产品定位与核心逻辑

### 1. 产品定位

UrbanScope AI 是一个面向城市规划前期现状分析的 AI 空间分析 Agent。它的核心不是聊天，也不是固定指标计算，而是把规划师提出的业务问题转化为可执行、可验证、可追溯的空间分析工作流。

一句话定位：

> 面向城市规划师的 AI 空间分析工作台，让规划问题自动转化为数据检查、GIS 分析、地图成果和可追溯结论。

### 2. 为什么需要 Agent

固定按钮适合上传数据、开关图层、打开属性表、导出结果等高频精确操作。Agent 的价值在于处理不确定性：

- 用户问题不一定对应固定功能。
- 所需数据不一定齐全。
- 字段含义可能需要确认。
- 分析路径可能需要临时组合多个 Tools。
- 结果经常需要继续追问。
- 结论必须说明依据和来源。

因此产品采用“UI + Agent”双层结构：

```text
高频精确操作 -> UI
复杂开放问题 -> Agent
```

### 3. 能力分层

```text
Tools：原子数据/GIS工具
Analysis Patterns：覆盖率、叠加、距离、密度、供需匹配等通用分析套路
Planning Skills：城市体检、公共服务评估、15分钟生活圈等规划专题方法
Agent：根据用户问题选择 Skill 或动态组合 Pattern + Tools
```

城市体检只是第一个 Planning Skill，不是产品边界。

## 五、功能说明

### 功能 1：Agent 对话式分析

**功能描述**

用户在 Agent 页面输入自然语言规划问题，Agent 以左侧气泡流式回复。回复中包含正文结论，以及可折叠的数据检查、分析计划、执行 Trace、结果依据。用户消息显示在右侧气泡。

**用户流程**

```text
进入 Agent 页面
  ↓
输入规划问题
  ↓
Agent 构建上下文并生成回复
  ├─ 数据齐全 -> 展示 Plan -> 请求确认或直接执行 -> 输出 Trace 和结果
  ├─ 数据缺失 -> 提示上传/启用平台数据/使用示例/跳过
  └─ 问题不明确 -> 追问用户分析对象或目标
```

**状态机**

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| 空闲 | 页面打开 | 用户发送消息 | 输入框可用 |
| 理解中 | 收到用户消息 | Planner 输出结果 | Agent 气泡显示“正在理解问题” |
| 等待补充 | 数据或字段缺失 | 用户选择处理方式 | 显示缺失数据和操作按钮 |
| 执行中 | Plan 可执行 | Executor 完成或失败 | Trace 流式更新 |
| 完成 | 工具执行成功 | 用户继续追问 | 输出结论和右侧成果 |
| 失败 | Tool 或数据异常 | 用户重试或修改数据 | 显示失败步骤 |

**字段规范**

| 字段名 | 类型 | 是否必填 | 长度限制 | 校验规则 | 错误提示 |
|---|---|---|---|---|---|
| 用户输入 | 文本 | 是 | 2000 字 | 不能为空 | 请输入想分析的问题 |

**文案规范**

| 场景 | 文案内容 |
|---|---|
| 空状态 | 请输入想研究的规划问题，例如“帮我分析这个片区公共服务有什么问题”。 |
| 加载中 | 正在理解问题并检查当前项目数据。 |
| 操作成功 | 分析完成，已生成地图图层和成果。 |
| 操作失败 | 分析失败，请查看失败步骤或重试。 |
| 权限不足 | 当前版本暂不启用权限系统。 |
| 网络异常 | 服务连接失败，请稍后重试。 |

**异常情况处理**

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| 问题不明确 | 无法识别分析对象 | Agent 追问 | “你想分析哪类对象或哪个专题？” |
| 数据缺失 | required_data 不存在 | 提供上传/启用/示例/跳过 | “缺少人口数据，无法继续。” |
| 字段不明确 | 无法识别关键字段 | 请求用户选择字段和值 | “请选择表示居住用地的字段和值。” |
| Tool 失败 | 工具返回错误 | 停止执行并记录 Trace | “coverage() 执行失败，原因：输入图层为空。” |

### 功能 2：数据就绪性检查

**功能描述**

Agent 每次执行 Planning Skill 或 Open Analysis 前，必须检查是否有足够数据支撑分析。检查内容包括图层是否存在、几何类型、坐标系、字段、空值、空间范围、字段语义和替代数据可能性。

**用户流程**

```text
Agent 识别分析意图
  ↓
生成所需数据清单
  ↓
检查当前 Data Registry
  ├─ 满足 -> 进入 Plan
  ├─ 部分满足 -> 提示缺失项和可替代项
  └─ 不满足 -> 阻断分析并引导补充数据
```

**状态机**

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| 待检查 | Planner 生成数据需求 | 检查完成 | 显示检查中 |
| 已就绪 | 所需数据满足 | 进入执行 | 显示可执行 |
| 部分就绪 | 可执行部分分析 | 用户确认跳过或补充 | 显示可执行项和缺失项 |
| 不就绪 | 核心数据缺失 | 用户补充数据 | 阻断并显示补充选项 |

**字段规范**

本功能无用户输入字段；当字段映射不明确时，触发字段映射选择。

**文案规范**

| 场景 | 文案内容 |
|---|---|
| 空状态 | 暂无待检查任务。 |
| 加载中 | 正在检查图层、字段和坐标系。 |
| 操作成功 | 当前数据满足分析要求。 |
| 操作失败 | 当前数据不足，无法执行分析。 |
| 权限不足 | 当前版本暂不启用权限系统。 |
| 网络异常 | 数据服务连接失败，请稍后重试。 |

**异常情况处理**

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| 缺少图层 | Data Registry 未找到 | 提供上传/平台数据/示例/跳过 | “缺少轨道站点图层。” |
| 几何类型错误 | 需要 polygon 但为 point | 阻断或建议替代处理 | “居住用地应为面数据。” |
| 坐标系不一致 | CRS 不同 | 提示转换 | “是否转换后继续？” |
| 字段缺失 | 必要字段不存在 | 请求补充字段或上传新数据 | “缺少人口数量字段。” |

### 功能 3：数据图层管理

**功能描述**

用户在“数据”页面管理所有空间数据。平台数据、用户上传数据和分析生成数据都以图层形式出现。平台数据是后续内置的基础数据，如 POI、人口、道路、公交、地铁；其他图层不在一级分类里强制区分。

**用户流程**

```text
进入数据页面
  ↓
查看图层列表
  ↓
点击图层菜单
  ├─ 显示/隐藏 -> 地图更新
  ├─ 缩放至图层 -> 地图定位
  ├─ 图层样式 -> 打开样式面板
  ├─ 预览数据 -> 打开属性表
  └─ 删除/重命名/复制 -> 更新图层列表
```

**状态机**

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| 无图层 | 项目没有数据 | 上传或启用数据 | 空状态 |
| 已加载 | 图层读取成功 | 用户操作图层 | 图层列表 |
| 菜单打开 | 点击更多按钮 | 选择操作或关闭 | 下拉菜单 |
| 属性表打开 | 点击预览数据 | 关闭属性表 | 表格弹窗/侧栏 |
| 操作失败 | 图层操作失败 | 重试 | 错误提示 |

**字段规范**

| 字段名 | 类型 | 是否必填 | 长度限制 | 校验规则 | 错误提示 |
|---|---|---|---|---|---|
| 图层名称 | 文本 | 是 | 50 字 | 不能为空，项目内不重复 | 请输入有效图层名称 |

**文案规范**

| 场景 | 文案内容 |
|---|---|
| 空状态 | 暂无图层，请上传数据或启用平台数据。 |
| 加载中 | 正在读取图层。 |
| 操作成功 | 图层已更新。 |
| 操作失败 | 图层操作失败，请重试。 |
| 权限不足 | 当前版本暂不启用权限系统。 |
| 网络异常 | 图层服务连接失败。 |

**异常情况处理**

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| 图层为空 | feature_count = 0 | 显示空图层标记 | “该图层没有记录。” |
| 无效几何 | 几何解析失败 | 标记不可分析 | “图层存在无效几何。” |
| 删除被引用图层 | 成果引用该图层 | 二次确认 | “删除后相关成果将无法定位。” |

### 功能 4：分析入口

**功能描述**

“分析”页面不是传统 GIS Toolbox，而是 Planning Skills 与常用 Analysis Patterns 的启动器。用户点击某个 Skill 或 Pattern 后，系统把它转化为一条 Agent 任务，在 Agent 对话中继续执行。

**用户流程**

```text
进入分析页面
  ↓
选择 Planning Skill 或 Analysis Pattern
  ↓
系统生成 Agent 任务
  ↓
跳转/聚焦 Agent 对话
  ↓
Agent 执行数据就绪性检查
```

**状态机**

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| 浏览能力 | 打开分析页面 | 选择能力 | Skill 列表 |
| 已选择 | 点击 Skill | Agent 创建任务 | 显示已发送到 Agent |
| 不可用 | 缺少核心数据 | 用户补充数据 | 显示数据需求 |

**字段规范**

本功能无用户输入字段。

**文案规范**

| 场景 | 文案内容 |
|---|---|
| 空状态 | 暂无可用分析能力。 |
| 加载中 | 正在加载分析能力。 |
| 操作成功 | 已发送到 Agent。 |
| 操作失败 | 启动分析失败，请重试。 |
| 权限不足 | 当前版本暂不启用权限系统。 |
| 网络异常 | 分析能力加载失败。 |

**异常情况处理**

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| Skill 不可执行 | 缺少 required_data | 进入 Agent 数据检查 | “该分析需要先补充数据。” |
| Pattern 不明确 | 需要用户选择图层 | Agent 追问 | “请选择要叠加分析的两个图层。” |

### 功能 5：右侧成果栏

**功能描述**

右侧成果栏显示当前分析或历史成果的结构化输出，包括 Widgets、指标卡片、图表、分析结论、证据来源和对应图层。成果不显示在底部面板。

**用户流程**

```text
完成一次分析
  ↓
右侧成果栏生成结果组
  ↓
用户查看指标/图表/结论
  ├─ 点击查看图层 -> 地图高亮
  ├─ 点击打开表格 -> 数据属性表
  └─ 折叠/展开结果组
```

**状态机**

| 状态名称 | 进入条件 | 退出条件 | 用户可见表现 |
|---|---|---|---|
| 无成果 | 未完成分析 | 分析完成 | 空状态 |
| 有成果 | 分析完成 | 用户切换结果 | 结果列表 |
| 高亮中 | 点击成果定位 | 取消高亮 | 地图联动 |
| 引用失效 | 结果图层被删除 | 恢复或忽略 | 显示失效标记 |

**字段规范**

本功能无用户输入字段。

**文案规范**

| 场景 | 文案内容 |
|---|---|
| 空状态 | 完成分析后，成果会显示在这里。 |
| 加载中 | 正在生成成果。 |
| 操作成功 | 已定位到对应图层。 |
| 操作失败 | 成果打开失败。 |
| 权限不足 | 当前版本暂不启用权限系统。 |
| 网络异常 | 成果服务连接失败。 |

**异常情况处理**

| 异常场景 | 触发条件 | 处理方式 | 用户反馈 |
|---|---|---|---|
| 图层缺失 | 成果引用图层不存在 | 禁用定位按钮 | “对应图层已删除。” |
| 图表无数据 | 统计结果为空 | 显示空图表状态 | “暂无可展示数据。” |

## 六、Agent 架构需求

### 1. 架构组成

```text
User Message
  -> Context Builder
  -> Planner
  -> Data Readiness Checker
  -> Executor
  -> Tool Registry
  -> Result Composer
  -> Memory Writer
```

### 2. Planner

Planner 负责判断用户意图、选择 Planning Skill 或 Analysis Pattern、生成所需数据清单、分析计划、工具调用计划和预期输出。Planner 不直接计算 GIS。

### 3. Executor

Executor 按 Planner 的计划逐步执行，调用 Tool Registry，并向 Agent 对话流式输出执行状态。Executor 需要记录每一步输入摘要、输出摘要、状态、失败原因和生成图层。

### 4. Tool Registry

Agent 面向统一 Tool Registry 调用工具。底层可接入或参考 gis-mcp，也可使用本地 Python 工具、GeoPandas、Shapely、PyProj、DuckDB Spatial、PostGIS 或 Demo mock tools。

P0 Tools：

- list_datasets
- get_dataset_schema
- preview_table
- check_crs
- spatial_clip
- buffer
- spatial_join
- overlay
- coverage
- nearest_distance
- statistics

### 5. Memory

Agent 需要项目级上下文记忆：

| Memory 类型 | 记录内容 | 示例 |
|---|---|---|
| Conversation Memory | 当前对话、用户确认、指代关系 | “这些区域”指刚才生成的未覆盖区 |
| Project Memory | 项目名称、边界、CRS、已加载图层 | 当前项目 CRS 为 EPSG:4490 |
| Analysis Memory | 已执行分析、结果图层、指标值、Trace | 中学覆盖率 82%，结果图层为 school_uncovered_area |
| Mapping Memory | 字段映射、规范口径、用户偏好 | land_use = R2 表示居住用地 |

## 七、Planning Skill 与 Open Analysis

### 1. Planning Skill 模式

用于方法论明确的专题分析，例如街区城市体检、15 分钟生活圈、公共服务设施评估。Skill 定义 required_data、workflow、tools、outputs、异常处理。

### 2. Open Analysis 模式

用于用户自由追问和临时分析。Agent 根据数据语义、Analysis Patterns 和 Tools 动态组合分析路径。

高置信 Demo 样例：

- 公共服务薄弱区是否与人口高密区重叠？
- 产业用地与轨道站点的可达性关系如何？
- 人口密度高的街区公园覆盖是否不足？

这些不是固定按钮，而是开放能力的演示样例。

## 八、街区城市体检 Skill

### 1. Skill 结构

```text
街区维度城市体检 Skill
  ├─ 中学服务半径覆盖率 Indicator Skill
  ├─ 公园绿化活动场地服务半径覆盖率 Indicator Skill
  ├─ 未达标配建的文化活动中心数量 Indicator Skill
  └─ 存在乱停乱放车辆问题的道路数量 Indicator Skill
```

父 Skill 负责统筹数据检查、可执行性判断、整体计划、子 Skill 调度、结果汇总和综合诊断。

### 2. MVP 实现深度

| 指标 | MVP 策略 | 输出 |
|---|---|---|
| 中学服务半径覆盖率 | 真实计算 | 覆盖率、覆盖居住用地、未覆盖居住用地、服务范围 |
| 公园绿化活动场地服务半径覆盖率 | 真实计算 | 覆盖率、覆盖居住用地、未覆盖居住用地、服务范围 |
| 未达标配建的文化活动中心数量 | 半真实审查 | 数量、缺口、面积/开放状态审查、未达标清单 |
| 乱停乱放车辆问题道路数量 | 缺数据阻断 + 可选模拟数据 | 缺失提示、所需数据清单、可选示例结果 |

### 3. 统一工作路径

每个 Indicator Skill 采用：

```text
数据准备
-> 指标计算 / 统计
-> 空间诊断
-> 规范审查 / 历史对比
-> 报告片段生成
```

所有数值必须来自确定性工具结果，AI 只能解释结果，不得编造。

## 十一、MVP Demo 故事

主线：

```text
用户：帮我对这个片区做一次街区城市体检。
Agent：检查 4 个指标所需数据。
Agent：3 项可执行，1 项缺少现场调研数据。
用户：先执行可用指标。
Agent：真实计算中学、公园覆盖率，审查文化活动中心，阻断乱停乱放指标。
系统：地图生成结果图层，右侧成果栏生成指标和结论。
```

Open Analysis 追问：

```text
用户：这些公共服务薄弱区是不是人口也比较集中？
Agent：读取薄弱区图层和人口图层，执行空间叠加和统计，输出人口集中度结论。
```

跨专题分析：

```text
用户：产业用地和轨道站点的空间关系怎么样？
Agent：检查产业和轨道数据，若缺轨道站点则询问上传/启用平台数据/使用公交替代；若齐全则计算最近距离和覆盖比例。
```
