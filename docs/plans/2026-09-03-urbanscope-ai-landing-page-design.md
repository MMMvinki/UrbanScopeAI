# UrbanScope AI 比赛 Landing Page 设计方案

**日期：** 2026-09-03  
**状态：** 已确认  
**目标：** 为 AI 比赛制作一个可独立浏览、可配合现场讲解的 8–10 分钟产品介绍页。

## 1. 项目目标

Landing Page 采用“价值开场、技术立证、场景落地”的叙事路线，重点回应比赛评审中的场景价值、应用成效、成果完成度、创新性、可推广性与安全合规性。

页面不是产品功能说明书，也不把三个分析方向描述为产品能力边界。它需要让评委理解：

1. 城市规划前期分析为什么需要 AI Agent；
2. UrbanScope AI 如何真正参与从问题到成果的分析过程；
3. Agent、Tools、Skills 与 Memory 如何协同；
4. 产品已经具备哪些真实能力；
5. 这些能力如何组合为专业规划分析场景；
6. 分析结果为什么可信，以及能力如何继续扩展。

## 2. 产品定位与核心文案

### 2.1 产品定位

UrbanScope AI 是面向城市规划前期研究的空间分析 AI Agent。它从规划师提出的问题出发，自主获取和检查数据、规划分析步骤、调用通用 Tools 与专业 Skills，并生成可交互地图、图表和有依据的分析结论。

### 2.2 Hero

**主标题：**

> 从一句规划问题出发，  
> 让 AI Agent 真正完成城市数据分析。

**说明：**

> UrbanScope AI 是面向城市规划前期研究的空间分析 AI Agent。它能够自主获取与检查数据、规划分析步骤、调用通用 Tools 与专业 Skills，并生成可交互的地图、图表和有依据的分析结论；还可以通过 AI 创建 Skill，适配更多个性化、垂直领域的专业分析场景。

**CTA：**

- 主按钮：开始使用
- 次按钮：查看分析案例

“开始使用”跳转地址通过配置提供，Landing Page 不写死当前工作台地址。“查看分析案例”滚动至代表性分析场景。

### 2.3 Hero 能力标签

- 理解规划问题
- 获取与检查数据
- 处理与分析数据
- 生成地图与图表
- 调用专业 Skills
- AI 创建 Skill

## 3. 用户问题与产品价值

### 3.1 项目背景

城市规划师在项目前期研究中，需要综合人口、用地、建筑、设施、交通、商业等城市数据，为问题诊断和规划决策提供依据。传统工作通常依赖专业 GIS 软件，由规划师人工完成数据接入、数据准备、空间计算、地图表达和结论整理，流程长、重复操作多，也难以借助普通 AI 工具实现端到端自动化。

### 3.2 三个高频低效场景

#### 数据获取与接入困难

数据来源分散、格式各异，需要反复查找、下载、上传并判断是否适用于当前任务。

#### 数据处理与准备繁琐

字段清洗、格式转换、坐标统一、范围裁剪和质量检查反复出现，是分析前最容易被低估的工作。

#### 地理空间分析复杂且耗时

城市空间分析通常依赖专业 GIS 软件。即使分析目标已经明确，规划师仍需手动完成数据检查、字段处理、坐标转换、范围裁剪、空间叠加、参数设置和地图表达等连续操作；复杂专题还需要多轮试算与调整，耗时且依赖个人经验。

### 3.3 价值承接

> 规划师需要的不是一个只会回答问题的 AI，而是一个能够实际参与分析工作的 Agent。

## 4. 用户使用流程

页面从用户视角展示以下流程：

1. 提出规划问题；
2. Agent 理解任务并检查现有数据；
3. 获取、上传或启用所需数据；
4. 查看并确认 AI 生成的分析计划；
5. 查看地图、图表和诊断结论；
6. 继续追问、调整参数或扩展分析。

这一部分不出现 Planner、Executor、Tool Registry、Tool Trace 等实现术语。

## 5. AI 技术机制：Agent × Tools × Skills × Memory

### 5.1 四个组成部分

| 机制 | 技术职责 | 用户能够感受到的价值 |
|---|---|---|
| Agent | 理解问题、检查数据、制定步骤、调度执行 | 一句话即可启动并持续推进分析 |
| Tools | 执行数据获取、处理、空间计算、地图控制与成果生成 | 能实际完成任务，而不只是生成文字 |
| Skills | 封装专业场景的数据要求、指标口径与分析流程 | 专业方法可复用、可定制 |
| Memory | 记录会话摘要、生成图层与样式操作 | 记住前面的成果，支持连续追问 |

### 5.2 对外表达

> 不只是一次问答，而是一段可以持续推进的分析过程。Agent 理解和组织任务，Tools 执行通用数据与空间分析，Skills 提供可复用、可定制的专业方法，Memory 则让 Agent 记住已经使用的数据、生成的图层和前面的分析结论，在连续追问中继续完成工作。

### 5.3 两种分析模式

#### 开放问题：Agent 动态组合 Tools

适合临时分析、数据探索、开放问题、跨专题组合和连续追问。Agent 根据问题和当前数据动态组合所需工具。

#### 专业场景：Agent 调用 Skills

适合城市体检、公共服务设施评估、15 分钟生活圈等需要稳定方法、数据要求和指标口径的垂直场景。

### 5.4 AI 创建 Skill

AI 创建 Skill 是独立创新模块：

1. 规划师提出新的专业分析需求；
2. Agent 确认输入数据、参数和分析口径；
3. 组合已有 Tools 或分析脚本；
4. 创建并校验新的 Skill；
5. 在后续项目中重复调用和迭代。

核心价值表达：

> 一次分析解决一个问题，一项 Skill 沉淀一种专业能力。

## 6. 产品真实能力图谱

### 6.1 数据获取与接入

- 平台内置城市数据；
- 本地数据目录发现和启用；
- CSV、Excel、GeoJSON、SHP、GPKG 上传；
- 经纬度字段识别与空间数据转换；
- 高德 POI、行政区划、地理编码和逆地理编码；
- OpenStreetMap 道路、建筑、设施等开放数据；
- 预置公开 GeoJSON 数据目录。

### 6.2 数据检查与处理

- 图层列表、字段、几何类型和要素数量检查；
- 属性查询和要素提取；
- CSV/Excel 转 GeoJSON；
- 空间裁剪与空间连接；
- 生成结果图层并注册到地图。

### 6.3 空间分析

- 缓冲区与覆盖率；
- 真实路网等时圈；
- 最近距离；
- 空间密度与核密度；
- 供需匹配；
- DBSCAN/K-Means 空间聚类；
- 双变量 Moran's I 与 LISA；
- 多图层统计和结果汇总；
- 受控代码执行与 GIS MCP 工具桥接。

### 6.4 地图与成果表达

- 图层显隐、排序、筛选、定位和高亮；
- 单值、分类、分级、热力图和视觉变量样式；
- 地图标注与底图切换；
- 指标卡、图表、分析结论和报告片段；
- 分析结果作为新图层返回地图并继续分析。

### 6.5 专业 Skills

当前已具备或已经进入项目实现的专业能力包括：

- 街区城市体检；
- 公共服务设施评估；
- 15 分钟生活圈；
- 核密度分析；
- 空间聚类；
- 人口热力分析；
- 街景绿视率与天空可视因子；
- Skill 创建、校验、执行和迭代。

街景分析依赖外部街景数据授权，演示宜使用已经验证的预计算成果。

## 7. 代表性分析场景

三个方向只作为产品众多可组合能力中的代表性示例，不称为“三大核心能力”。模块开头统一说明：

> UrbanScope AI 可以组合完成多种城市数据分析。以下从众多能力中选取三个方向，展示产品在真实规划场景中的应用。

### 7.1 城市形态、功能与空间品质

以建筑形态、商业业态结构和城市功能混合度为例，回答城市空间如何构成、功能如何分布，以及哪些区域复合或单一。

### 7.2 人口与时空活力

以居住与就业人口画像、人口密度为例，回答服务谁、人群在哪里，以及居住和就业人口如何集聚。

### 7.3 可达性与人—空间耦合诊断

以轨道交通可达性、轨道可达性—商业服务错位为例，识别轨道服务盲区和高可达—低商业供给等空间错位区域。

三个场景构成递进：

> 看懂空间 → 看懂人群 → 诊断人与空间的匹配关系。

建筑综合形态、完整人口画像和城市功能混合度目前以 Agent 组合现有数据与通用 Tools 的方式实现，不宣传为全部已经封装完成的一键 Skill。录制视频前必须逐条跑通并核对输出。

## 8. 视频组织

采用三支主题视频，每个代表性方向一支，建议 45–90 秒。

- 案例一：左侧说明，右侧视频；
- 案例二：左侧视频，右侧说明；
- 案例三：左侧说明，右侧视频。

视频尚未制作时使用统一 16:9 占位框，显示案例名称、简化地图底纹和“演示视频制作中”。后续只替换资源，不改变布局。

视频进入视口后可静音自动播放；用户点击后打开带声音与进度控制的完整视频。必须提供暂停控制，并尊重系统减少动态效果设置。

## 9. 页面内容顺序

1. 顶部导航与“开始使用”按钮；
2. Hero；
3. 为什么做；
4. 从问题到成果的用户流程；
5. Agent × Tools × Skills × Memory；
6. 开放问题与专业场景两种分析模式；
7. 产品完整能力图谱；
8. AI 创建 Skill；
9. 三个代表性分析场景；
10. 为什么结果值得信任；
11. 产品价值与推广空间；
12. 结尾 CTA。

## 10. 可信与安全表达

不以评测系统或运行归档作为宣传卖点。面向用户只表达：

- 数据来源清楚；
- 分析步骤透明；
- 参数和口径可以查看、确认与调整；
- GIS 数值来自真实数据和真实计算；
- 结论可以回到地图、图层和图表中验证；
- 写入和代码执行需要用户确认；
- 平台基础数据只读保护；
- 不同项目的数据和上下文相互隔离。

## 11. 视觉方向

参考 [CARTO 官网](https://www.carto.com/) 的页面节奏、空间背景、产品大图和滚动交互，但不复制其品牌视觉。

采用“深色 Hero + 浅色主体 + 局部深色技术区”：

- 深色 Hero 使用低对比城市路网、等高线、网格或空间点背景；
- Hero 底部露出大型产品工作台画面；
- 浅色主体承载痛点、流程、能力与案例；
- Agent × Tools × Skills × Memory 使用深色技术区；
- 三个案例采用左右交错布局；
- 结尾 CTA 回到深色品牌区。

### 11.1 主题色

| 用途 | 颜色 |
|---|---|
| 深海军蓝 | `#0F172A` |
| 灰蓝色 | `#64748B` |
| 鼠尾草绿 | `#059669` |
| 浅灰背景 | `#F8FAFC` |
| 白色卡片 | `#FFFFFF` |
| 信息蓝 | `#0EA5E9` |

Agent 流动球可以保留现有浅蓝、绿色和少量紫色光泽，作为 AI Agent 的专属动态标识；紫色不扩展为全站主色。

### 11.2 动效

- Hero 地图背景缓慢漂移或视差；
- 产品工作台轻微浮入；
- 用户流程随滚动依次点亮；
- Agent、Tools、Skills、Memory 节点和连线依次出现；
- 能力标签切换时同步更新产品画面；
- 案例区块使用克制的淡入、上移和轻微缩放；
- 不使用粒子爆炸、持续旋转或高饱和霓虹；
- 移动端关闭复杂视差；
- 支持 `prefers-reduced-motion`。

## 12. 技术与项目边界

Landing Page 独立于现有工作台，建议位于 `apps/landing`，拥有独立的依赖、开发和构建入口。

- 不改动现有 `apps/web` 的默认入口和路由；
- 复用品牌字体、颜色、产品截图和必要的视觉资产；
- “开始使用”地址由环境配置或集中常量提供；
- 演示视频放在 Landing Page 自己的公共资源目录；
- 页面首版不接入后端，不需要登录和持久化；
- 页面内容以静态数据驱动，便于后续替换文案、截图与视频。

## 13. 响应式与无障碍

- 桌面端以 1440px 展示效果为优先，同时适配常见笔记本宽度；
- 平板和手机端将左右分栏改为上下排列；
- 固定导航在小屏简化为菜单；
- 所有按钮、标签和视频控件支持键盘操作；
- 文字与背景满足基本对比度要求；
- 图片和视频提供替代文本；
- 视频默认静音自动播放，用户可暂停并打开完整控制；
- 动效不会成为理解内容的唯一方式。

## 14. 空状态与降级

- 视频缺失时显示正式设计的案例占位画面；
- WebGPU Agent 球不可用时显示静态品牌球或图标；
- 工作台跳转地址未配置时，“开始使用”按钮显示不可用说明，不跳转到错误地址；
- 动效库或脚本失败时，所有内容仍然完整可读；
- 产品截图加载失败时保留对应文字说明和占位背景。

## 15. 验收标准

1. 评委在首屏能理解产品服务谁、解决什么问题；
2. 页面明确区分平台能力图谱与代表性分析案例；
3. 页面能解释 Agent、Tools、Skills 与 Memory 的关系；
4. 页面突出通用分析、专业 Skill 和 AI 创建 Skill 三种能力；
5. 所有对外能力文案均能在当前项目中找到实现依据；
6. 三个案例均支持视频占位并可无损替换为正式视频；
7. 页面在没有后端服务时仍可完整浏览；
8. “开始使用”能够通过配置跳转到现有产品；
9. 页面在桌面、平板和手机上可阅读；
10. 减少动态效果模式下不影响内容完整性；
11. 不宣传 Agent 评测与运行归档；
12. 现场边讲边滚动的完整时长约为 8–10 分钟。
