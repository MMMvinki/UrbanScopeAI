# UrbanScope AI · 3 分钟演示脚本

> 适用版本：全 LLM Agent + 真 GIS。规划与执行由 DeepSeek 驱动（真实 LLM 叙事 + agentic 工具调用循环）；覆盖率/距离/占比等数值来自 **GeoPandas/Shapely 对后端真实 GeoJSON 的真几何计算**（EPSG:4490 → UTM 50N 米制运算），LLM 不编造数字。外部 GIS 工具（gis-mcp，88 个 `gis_*` 工具）已通过 MCP 桥接入 Agent。

## 0. 演示准备（演示前完成，不占用 3 分钟）

```bash
# 终端 1 —— 后端
cd apps/api
./.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 终端 2 —— 前端
cd apps/web
npm run dev        # http://localhost:5173
```

浏览器打开 `http://localhost:5173`，应看到：左窄导航 + 左侧 Agent 对话面板 + 中央地图 + 右侧成果栏。

> 数据说明：图层几何为确定性合成数据（`app/scripts/generate_demo_geojson.py`，固定种子，坐标落在北京核心区 116.31–116.37E / 39.90–39.95N），但**空间关系与计算是真实的**——覆盖率由「设施 buffer ∩ 居住用地」的真几何求交算出。规划/执行调用 DeepSeek API（需网络与 `apps/api/.env` 中的 `DEEPSEEK_API_KEY`）。LLM 不可用或 API 异常时自动回退规则版 Planner/Executor（演示永不挂）；后端未启动时前端自动退回本地演示数据（UI 仍可浏览，但新提问会返回"后端服务不可用"提示）。

## 1. 主线故事（约 3 分钟）

**开场（0:00–0:30）· 布局讲解**
> 页面是四栏工作台：最左是项目/Agent/数据/分析四个工作区入口；中间左侧是 Agent 对话，Agent 用 Codex 式流式输出展示规划过程（含可展开的 Planner 思考过程）；中央是地图，分析生成的图层会实时同步（deck.gl 叠加渲染，无 WebGL 时自动回退 MapLibre/示意地图）；右侧是成果栏，每次分析产出可追溯的结果卡片。

**第 1 步（0:30–1:15）· 城市体检主线**

在对话输入框输入：

```
帮我对这个片区做一次街区城市体检，重点看学校和公园的服务覆盖情况
```

**期望过程（流式播放）：**
1. 先出现"正在理解问题并检查当前项目数据…"；
2. 消息展开，包含「Planner 思考过程」「数据检查」「分析计划」三个可折叠区块：
   - Planner 思考：DeepSeek 实时撰写，说明为什么判定为 `community_health_check` Skill、按默认 targets/距离对齐计划；
   - 数据检查：5 项就绪（研究范围/居住用地/学校设施/公园绿地/文化活动中心），1 项缺失（乱停乱放）；
   - 分析计划：DeepSeek 实时撰写（实际抓取到 4 步），步骤随问题变化；
3. 过程块依次播放（LLM 叙事文本与工具调用交替出现，数值全部来自真计算工具返回）：
   ```
   check_readiness("auto")
   数据检查报告（+3 就绪 · 1 缺失）
   缺失数据：乱停乱放，先执行可用部分。
   coverage(schools, 800m)   → 学校设施服务范围（+24 要素）
   coverage(parks, 500m)     → 公园绿地服务范围（+38 要素）
   coverage(culture_centers, 1000m) → 文化活动中心服务范围（+16 要素）
   （LLM 自主追加）supply_demand / spatial_join / nearest_distance …
   （LLM 最终结论，引用真计算数值）学校覆盖率 94.4%、公园 95.0%……
   分析完成，结果图层已同步到地图…
   ```

**期望成果（右侧成果栏 + 地图）：**
| 卡片 | 数值 |
|---|---|
| 学校设施服务覆盖率 | **94.4%**（800m 服务半径，覆盖 12.06 km²） |
| 公园绿地服务覆盖率 | **95.0%**（500m 服务半径，覆盖 12.13 km²） |
| 文化活动中心服务覆盖率 | **97.4%**（1000m 服务半径，覆盖 12.44 km²） |
| 供需满足度 / 最近距离 / 叠加占比 | 由 LLM 自主追加的补充分析（如 schools 供需 96.1%、最近居住用地 422m） |
| 指标对比 | 各百分比指标条形图 |
| 结果图层 | `schools_coverage`、`parks_coverage`、`culture_centers_coverage` 已同步到地图 |

可操作演示点：点击结果卡「查看图层」跳到数据面板并点亮对应图层；点「定位地图」地图飞至该图层；展开卡片下方「结果依据」查看证据链。

**第 2 步（1:15–2:10）· 人口与薄弱区追问（开放分析 1）**

继续提问：

```
哪些片区人口最薄弱，主要分布在哪里？
```

**期望过程：** LLM 自主判定为 `density`（密度分析，对"人口薄弱"的合理解读；也可能判 `overlay`），目标图层 `population_grid`；`density(population_grid)` 真计算人口加权密度 **3677 人/km²**，`spatial_join(population_grid, residential)` 叠加占比 **74.7%**，生成结果图层（+144 要素）。
**期望成果：** 结果组「密度分析」—— 人口网格密度指数 **3677 人/km²** + 叠加占比 **74.7%** + 指标对比 + 结果图层。

**第 3 步（2:10–2:50）· 产业与轨道追问（开放分析 2）**

继续提问：

```
产业用地到最近轨道站点的通勤距离
```

**期望过程：** 操作判定为 `nearest_distance`（最近距离分析），目标图层 `industry` + `transit_stations`；`nearest_distance(industry, transit_stations)` 真计算平均距离 **523 m**，生成 `产业用地结果图层`（+38 要素），LLM 还自主追加 `coverage(transit_stations, 800m)` 生成 `轨道站点服务范围`（+12 要素）。
**期望成果：** 结果组「最近距离分析」——
- 最近产业用地距离 **523 m**（平均距离）；
- 轨道站点服务覆盖率 **78.9%**（800m 服务半径）；
- 指标对比 + 结果图层（`industry_result`、`transit_stations_coverage`）。

**收尾（2:50–3:00）· 总结**
> Agent 演示了"问题 → 数据就绪检查 → LLM 规划（含思考过程）→ agentic 工具调用 → 地图图层 → 可追溯结果"的完整闭环。Planner 与 Executor 均由 DeepSeek 驱动（LLM 决定操作/目标/调用哪些工具并撰写结论），所有覆盖率/距离/占比一律来自 GeoPandas/Shapely 真几何计算，LLM 不参与计算；无 key 或 API 异常时自动回退规则版，接口不变。需要外部空间能力（如 WKT 几何缓冲、坐标转换）时，Agent 可调用 gis-mcp 的 `gis_*` 工具。

## 2. 备用追问（任一路径失败或超时）

| 问题 | 期望判定 |
|---|---|
| `公园800米范围内能服务多少居民` | coverage / parks / 800m |
| `哪些片区人口最薄弱` | density 或 overlay / population_grid |
| `产业用地的密度分布` | density / industry |
| `文化活动中心够不够用` | coverage / culture_centers |

> 判定由 DeepSeek 自主完成，上表为常见结果；同名问题可能给出语义等价的另一 operation（如"薄弱"可判 density 或 overlay），属正常 LLM 行为，只需检查目标图层与数值正确。数值口径见第 4 节。

## 3. 故障回退（端到端）

| 症状 | 原因 | 处理 |
|---|---|---|
| 对话出现"后端服务不可用：Failed to fetch" | 后端未启动 / 端口占用 | `apps/api` 下启动 uvicorn，确认 `http://127.0.0.1:8000` 可访问；图层面板保留本地演示数据，页面仍可浏览 |
| 提问后消息停留在"正在理解问题…"不结束 | 后端阻塞或已崩溃 | 查看 uvicorn 日志；重启后端后重新提问（无需刷新页面） |
| 地图不显示新图层 | 图层已存在但未可见 | 数据面板勾选生成图层（`*_coverage` / `*_result`） |
| 地图显示"WebGL 不可用"示意地图 | 浏览器禁用硬件加速 / VM / 远程桌面 | 开启 Chrome/Edge「使用硬件加速」后刷新；deck.gl 与 MapLibre 均需 WebGL2 |
| 数字与脚本不一致 | 后端未重启，旧代码在跑 | 重启 uvicorn 后结果即恢复确定性真值（schools 94.4 / parks 95.0 / culture 97.4 / transit 78.9） |
| 演示失败但想继续 | LLM 未配置或 API 故障 | 自动回退规则版 Planner/Executor，过程块与数值不变（规则版也走同一真计算引擎）；确认 `apps/api/.env` 配好 `DEEPSEEK_API_KEY` 后恢复 LLM |
| 提问后长时间无响应 | DeepSeek API 慢 / 超时 | 单次请求最多 90s 超时 + 每轮最多 6 轮工具循环，超时自动回退；演示前先跑通一次三条路径 |
| 乱码/编码报错（Windows） | 控制台 GBK | 服务端日志与本脚本无关；浏览器端为 UTF-8 不受影响 |

## 4. 数值口径（演示判据）

所有数值由 `app/gis/engine.py` 对确定性 GeoJSON 做**真几何计算**：几何先投影到 UTM 50N（EPSG:32650，米制）保证 buffer/面积/距离量纲正确，再转回 EPSG:4490 输出；覆盖率 = 「设施服务半径 buffer ∩ 居住用地面积」÷ 居住用地总面积。数据固定，故数值可在直播中稳定复现：

| 指标 | 口径 | 值 |
|---|---|---|
| 学校设施服务覆盖率 | buffer 800m ∩ 居住用地 | **94.4%**（12.06/12.77 km²） |
| 公园绿地服务覆盖率 | buffer 500m ∩ 居住用地 | **95.0%**（12.13/12.77 km²） |
| 文化活动中心服务覆盖率 | buffer 1000m ∩ 居住用地 | **97.4%**（12.44/12.77 km²） |
| 轨道站点服务覆盖率 | buffer 800m ∩ 居住用地 | **78.9%** |
| 人口网格密度 | 总人口 ÷ 网格面积 | **3677 人/km²** |
| 学校供需满足度 | buffer 800m 覆盖人口 ÷ 总人口 | **96.1%** |
| 最近居住用地距离（学校） | 质心最近距离均值 | **422 m** |
| 最近产业用地距离（轨道站点） | 质心最近距离均值 | **523 m** |
| 人口网格 × 居住用地叠加 | 相交面积占比 | **74.7%** |

城市体检路径中，学校按指标定义用 **800m**、公园用 **500m**、文化中心用 **1000m**（`target_distances` 机制）。
LLM 只负责选择工具、生成计划与撰写结论，数值一律取工具返回值（`coverage` / `spatial_join` / `nearest_distance` / `density` / `supply_demand`），演示不会出现编造数字。
