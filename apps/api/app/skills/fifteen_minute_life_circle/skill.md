# 15 分钟生活圈分析

## 适用场景

用户以「15 分钟生活圈 / 生活圈 / 最后一公里」等**生活圈整体语义**发问（如"华侨城的 15 分钟
生活圈覆盖如何"）。核心诉求是：把一片区域内**所有**站点（地铁站/设施点）按真实路网算出 N 分钟
步行可达范围，并查看融合后的覆盖形态与服务盲区。

注意：仅问「地铁站等时圈 / 步行可达范围」这类**工具级**请求时，不命中本技能——那是 `isochrone`
工具的直接用途，走通用规划直接调工具即可。

## 执行流程

1. **就绪检查**：确认地铁站/设施点图层与研究范围图层是否存在；缺的项由平台提示，用户可
   跳过或上传。
2. **取中心点坐标**：用 `query_features` / `extract_features` 从站点图层读取各站真实经纬度
   （坐标必须是图层里的真实值，禁止臆造）。若只有全区站点图层，可先用范围做空间裁剪得到
   范围内的站点。
3. **一次调用生成等时圈**：调 `isochrone` 工具，把全部站点一次传入 `centers`
   （`[[经度, 纬度, '站名'], ...]`），`minutes` 按需（如 `[15]` 或 `[5,10,15]`），
   `profile=walking`。工具默认 `merge=true`：同一分钟档的多边形取并集——一个时间档一个
   融合形状（多档自动成环带），一次调用 = 一个图层，**严禁拆成多次调用**。
4. **覆盖分析**：把等时圈图层与范围/人口图层叠加，统计覆盖占比与盲区（如范围被等时圈覆盖
   的比例），用确定性工具算真实数值，禁止编造。
5. **结论**：汇总融合等时圈的形态、覆盖情况与不足，写入结果组。

## 注意事项

- 等时圈 = 按真实路网（Mapbox Isochrone API）的步行可达范围，比 `coverage`（直线缓冲）
  更真实；二者互补，按问题语义选用。
- 所有中心点必须一次传完（`centers` 数组），得到融合后的单一图层；同档融合后一个时间档
  就是一个形状，不再一站一个圈。
- 坐标为 WGS84 经纬度，必须从图层读取真实坐标，不要臆造。
